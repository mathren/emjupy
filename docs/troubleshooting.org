#+TITLE: Troubleshooting
#+PREVIOUS_PAGE: language-server.org
#+NEXT_PAGE: design.org

When something behaves unexpectedly.

Start with =C-c C-x s= (=emjupy-status=) in the notebook.  It shows the
notebook's server, its kernel and what the kernel is doing.  It shows
the language server: the server's own or a fallback, and why.  It shows
the remote machine the notebook is reached through, and emjupy's recent
messages.  Look at it first, and send it with a report.

* Something changed on a machine

emjupy remembers, for the session, what it learns about servers and
machines: which server answers, which has a language server, and each
machine's environments and conda.  That saves asking again at every
opening.  Sometimes those facts change: an environment is removed, a
server is reconfigured, or jupyter-lsp is installed.
=M-x emjupy-forget-remote-state= then forgets them all, and emjupy asks
again when it next needs them.  Live connections and tunnels are kept.
With =C-u=, emjupy also forgets the environment chosen for each folder.

* Diagnosing slowness

First find which part is slow.

=emjupy-language-support= nil disables every path that contacts a
language server.  That is: completion, eldoc, =M-.= (left to Emacs's
other xref backends), the server started when a notebook opens, and the
commands that ask a server for something, which then say there is none.
Notebooks, kernels, output and rendering stay as they are.  If the delay
goes away, it came from language support.  The setting takes effect at
once, in notebooks already open.  =emjupy-edit-cell-externally= still
opens all the code in one buffer, without a server.  Set back to t, a
server starts when one is next needed.

=emjupy-slow-hook-threshold= is a number of seconds.  emjupy reports
per-command work that takes longer, and names the function.

If neither points anywhere, measure:

#+begin_example
M-x profiler-start RET cpu RET
  ... move the point around until it feels slow ...
M-x profiler-report
#+end_example

A top entry that is an emjupy function is a bug worth reporting; attach
the report.  emjupy's own per-command work is small: a cursor move takes
well under a millisecond.  So on a notebook full of figures, the answer
is usually =redisplay_internal= or image scaling, which means more than
Emacs draws comfortably.  Clearing some output
(=emjupy-clear-all-outputs=) confirms it in seconds.

* =M-.= finds the standard library but not my own modules

The language server that answers runs on this machine, not beside the
kernel, so it cannot see the kernel's files.  =M-x emjupy-lsp-diagnose=
says "a local process", and =M-x emjupy-version= says "language server
on this machine".  Install =jupyter-lsp= and a language server where
=jupyter server= runs (see
[[file:language-server.org::*Requirements][Requirements]]), then restart
the server.

* A cell shows as running and never finishes

If the cell is not really still working, the kernel probably died: it
ran out of memory, or the code exited.  The server then restarted it
without telling the notebook.  =C-c C-x C-c= reconnects to the new
kernel and ends the run.  The old kernel's state is gone.
[[file:limitations.org][Known limitations]] explains why.  emjupy
notices by itself a kernel that was shut down from elsewhere, or culled:
after =emjupy-kernel-check-interval= seconds (30) of silence, the cell
ends and the notebook says the kernel is gone.

* Two installations of emjupy

Two installations on the =load-path=, such as a package and a checkout,
can make Emacs load some files from each.  The mix fails like a bug: a
key shows as =M-x= and a command's name, or widgets are drawn as text.
=M-x list-load-path-shadows= lists the files found twice.  Remove one
installation, or put the one you want first on the =load-path=.

* "The notebook was redrawn: its display had come apart from its cells"

After a redraw, when Emacs is idle, emjupy checks that the buffer still
matches the notebook's structure.  If it does not, emjupy redraws from
the cells (see [[file:design.org][How it works]]).  Nothing is lost: the
cells are the notebook, and text typed in cells that are still intact is
kept.  The message says what was wrong.  This should not happen, so
please report it, with the message and what you were doing.
