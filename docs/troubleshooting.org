#+TITLE: Troubleshooting
#+PREVIOUS_PAGE: language-server.org
#+NEXT_PAGE: design.org

When something behaves unexpectedly.

* Diagnosing slowness

First find which part is slow.

=emjupy-language-support= nil disables every path that contacts a
language server -- completion, eldoc, =M-.= (left to Emacs's other xref
backends), the server started as a notebook opens, and commands asking
one for something, which say there is none -- leaving notebooks, kernels,
output and rendering as they are.  If the delay goes, it came from
there.  It takes effect at once, in notebooks already open;
=emjupy-edit-cell-externally= still opens all the code in one buffer,
without a server.  Set back to t, a server starts when next asked for.

=emjupy-report-slow-hooks=, a number of seconds, reports per-command work
taking longer, naming the function.

If neither points anywhere, measure:

#+begin_src
M-x profiler-start RET cpu RET
  ... move the point around until it feels slow ...
M-x profiler-report
#+end_src

Top entries that are emjupy functions are a bug worth reporting, with the
report.  emjupy's own per-command work is small -- a cursor move well
under a millisecond -- so on a notebook full of figures the answer is
usually =redisplay_internal= or image scaling: more than Emacs draws
comfortably.  Clearing some output (=emjupy-clear-all-outputs=) confirms
it in seconds.

* =M-.= finds the standard library but not my own modules

The language server answering is on this machine, not beside the kernel,
and cannot see the kernel's files: =M-x emjupy-lsp-diagnose= says "a
local process", =M-x emjupy-version= "language server on this machine".
Install =jupyter-lsp= and a language server where =jupyter server= runs
-- see [[file:language-server.org::*Requirements][Requirements]] -- and restart the server.

* A cell shows as running and never finishes

If the cell is not really still working, the kernel likely died -- out of
memory, or the code exited -- and the server restarted it without telling
the notebook.  =C-c C-x C-c= reconnects to the new kernel and ends the
run; the old kernel's state is gone.  Why, in [[file:limitations.org][Known limitations]].

* "emjupy is loaded from two places"

Two installations are on the =load-path= -- a package and a checkout, say
-- each supplying some files.  A mix fails like bugs: a key shown as
=M-x= and a command's name, widgets drawn as text.  Remove one, or put the
one wanted first on the =load-path=; =M-x emjupy-version= names the files
loaded from elsewhere.

* "The notebook was redrawn: its display had come apart from its cells"

After redraws, when idle, emjupy checks the buffer still matches the
notebook's structure, and redraws from the cells if not (see [[file:design.org][How it works]]).
Nothing is lost: the cells are the notebook, and what was typed in cells
still intact is kept.  The message says what was wrong; it should not
happen, so please report it, with its text and what you were doing.
