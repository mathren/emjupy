* Cell appearance

Cells are marked out by their rules alone, on the buffer's normal
background.  Only a cell's *output* gets a faint band, on the output
overlay, so it goes with the outputs when they are cleared.

=emjupy-output-color= sets the band.  Its default, ='auto=, blends the
background =emjupy-output-blend= (8%) toward the foreground: darker on a
light theme, lighter on a dark one, tinted by the theme, and following
theme switches.

#+begin_src elisp
(setq emjupy-output-color "#f0f0f0")   ;; pin a colour
(setq emjupy-output-color nil)         ;; no band at all
#+end_src

The band fills each output line edge to edge: the =emjupy-output= face
sets =:extend t=.  =M-x emjupy-refresh-appearance= re-derives the colour
and redraws.  The faces are =emjupy-output= (the band) and
=emjupy-box-line= (the rules).

* Editing a rendered formula

A rendered fragment is an image over its source, which stays in the
buffer, editable but hidden.  =DEL= at the end of a rendered fragment
removes the image, point after the source's last character; a second
=DEL= deletes as usual.  =M-x emjupy-toggle-latex-preview= renders it
again.

* Scrolling past figures

A tall inline image is one screen line, so line scrolling passes it in
one step.  Either:

#+begin_src elisp
(pixel-scroll-precision-mode 1)          ; built in, Emacs 29 and later
#+end_src

or the =ultra-scroll= package, smoother with tall images and mixed line
heights, recommended for notebooks with figures:

#+begin_src elisp
(use-package ultra-scroll
  :config (ultra-scroll-mode 1))
#+end_src

emjupy enables neither: both are global.

* Inspecting the cell outlines

The rule above an output box is an overlay string, so =M-x describe-char=
cannot reach its columns.  =M-x emjupy-report-box-geometry= reports the
width the rules are drawn at, the rule's in place, and the column the
output background is aligned to.

* Cell outlines

=emjupy-box-width= sizes the rules: ='window=, the default, fits the
window rather than a fixed 80 columns; an integer fixes the width;
=emjupy-box-min-width= (60) is the floor when fitting.  Rules follow the
window -- splits, dragged mode lines, full screen -- so they do not wrap,
unless the window is narrower than the floor.  Only overlay strings are
rebuilt, so point, markers and undo are untouched.  Shown in two windows,
the *narrower* wins, as a rule sized for the wide one would wrap in it.

* Cell outline artifacts

An outline is an overlay property, drawn even when the overlay is empty,
so one whose cell is gone shows as a border with no cell.  A full redraw
deletes emjupy overlays no live cell owns: =M-x emjupy-re-render= clears
them.

* Line numbers

With =display-line-numbers-mode=, numbers fall on the lines you write and
on output, not the outlines: each rule is drawn as a continuation of the
line above, and the empty line between cells is hidden.  Numbers are the
buffer's own, skipping a value at a cell's end, and the rules narrow for
the number column.  Exceptions: the first cell's header, with no line
above, takes line 1's number, and the last cell's footer is on a numbered
line at the buffer's end.

* LaTeX in markdown cells

Off by default.  =M-x emjupy-toggle-latex-preview= turns it on, or:

#+begin_src elisp
(setq emjupy-render-latex t)
#+end_src

Math between =$...$=, =$$...$$=, =\\(...\\)= and =\\[...\\]= is then shown
*on screen* as an image -- inline for the first and third, displayed for
the others, as in LaTeX.  The image is an overlay: the cell holds, and
saves, the LaTeX written, and hovering shows the source.

org renders it, with Emacs, so only LaTeX is needed:

#+begin_src bash
sudo apt install texlive-latex-base dvipng
#+end_src

=math-preview= is used if that is what is installed -- it works well, but
needs nodejs and npm, so is not the default.  =emjupy-latex-backend=
chooses explicitly.

Formulae are drawn in the theme's foreground on a transparent background;
=emjupy-latex-foreground= overrides the colour, =emjupy-latex-scale= the
size.  Images are cached by content /and colour/: redrawing does not
re-run LaTeX, and a theme switch regenerates them.  =emjupy= uses a
minimal preamble (amsmath and amssymb), not org's full package list,
which a small TeX install lacks.

* Inline images need a graphical Emacs

Images are drawn only where Emacs can display them
(=display-graphic-p= *and* =image-type-available-p=): on a terminal frame
or an image-less build (=emacs-nox=), =create-image= *signals*, and in a
WebSocket callback that would leave the box blank.  So emjupy shows the
output's =text/plain= instead, with a note saying why.

Supported inline types: =image/png=, =image/jpeg=, =image/gif= and
=image/svg+xml=.

* Duplicate figures

A cell ending with a figure can receive it twice: as the
=execute_result= repr and as the inline backend's =display_data=.  emjupy
draws a repeat -- the same bytes; two sizes are two pictures -- once, at
*render* time only: the cell's outputs and the saved =.ipynb= keep what
the kernel sent.  =emjupy-deduplicate-image-outputs= =nil= draws both.
